# Herdr 협업 프로젝트 점검 보고서

2026-11-22 · 기준 브랜치 `main` · 커밋 `8760995`

이 프로젝트는 지휘자 한 명이 여러 에이전트에 작업을 보내고, 공유 폴더의 변경을 담당 범위와 대조하는 도구다. 문서에 명시된 운영 조건인 **순차 예약과 병렬 작업 실행**을 기준으로 검토했다. 우선 수정할 곳은 작업 제출을 확인하는 로직이다. 자동 Enter 재시도와 전송 기록 사이의 공백은 평소에는 드러나지 않지만, 승인 창이 늦게 뜨거나 전송 직후 프로세스가 중단될 때 운영자가 잘못된 조치를 취하게 할 수 있다.

## 수정 우선순위

| 순위 | 문제와 발생 조건 | 권장 수정 및 완료 기준 |
|---|---|---|
| 1 · 높음 | **자동 Enter 재시도가 현재 화면을 다시 확인하지 않는다.** 전송 직전에는 창을 검사하지만, 이후에는 상태와 차례 번호만 조회한다. 상태가 계속 idle이고 그 사이 승인·신뢰 창이 표시되면 재시도 키가 그 창에 전달될 수 있다. macOS와 Windows 양쪽에 같은 흐름이 있다. 실제 승인 발생 여부는 미검증이다. | 재시도 전에 화면을 다시 확인하고, 조회 실패 또는 사람의 입력이 필요한 창이면 자동 키 입력을 중단한다. 키 입력과 화면 확인을 원자적으로 묶을 수 없다면 입력 대상이 불명확할 때 수동 점검으로 전환한다. 모의 터미널에서 재시도 직전에 창을 표시하고 키 전송 0회를 검증한다. |
| 2 · 높음 | **전송 성공과 작업 기록 저장이 분리돼 있다.** 수신자가 작업을 받은 뒤 송신 프로세스가 종료되면 작업 원문과 범위 예약은 있지만 대상·차례를 담은 환경 파일은 없을 수 있다. 이때 wait는 보낸 기록을 찾지 못하고, 최종 보고가 아직 없으면 같은 ID로 send를 재시도할 수 있다. | 전송 직전에 시도 상태와 대상을 기록한다. 응답이 유실된 작업은 재시도 전에 기존 차례 또는 보고를 대조하도록 한다. 모의 전송 성공 직후 기록 실패를 주입하고, 같은 ID가 두 번 전송되지 않는지 확인한다. |
| 3 · 중간 | **작업 상태 JSON을 최종 경로에 직접 쓴다.** 기록 도중 종료되면 불완전한 JSON이 남을 수 있다. 이후 다른 작업도 전체 예약을 읽으면서 해당 파일에서 오류 8로 중단될 수 있다. 순차 예약 환경에서도 발생 가능한 장애다. | 같은 디렉터리의 고유한 임시 파일에 완전히 기록한 뒤 이름을 바꿔 게시한다. 중단 시험에서 기존 기록이 계속 읽히고 미완성 새 예약은 목록에 나타나지 않아야 한다. |
| 4 · 중간 | **agy 요약에서 구간을 못 찾은 경우와 실제 0회를 구분할 수 없다.** 파일 선택은 임의 줄의 작업 헤더 문자열로 하지만 실제 집계는 HandleUserInput 줄에서 시작한다. 더 최근 로그의 일반 출력에 같은 헤더가 인용되면 그 파일을 골라 모든 횟수를 0으로 표시할 수 있다. | 파일 선택과 집계에 동일한 작업 시작 조건을 적용한다. 일치 구간이 없으면 집계 불가를 표시한다. 오래된 실제 작업 로그와 더 최근의 인용 로그를 함께 넣어 올바른 파일을 고르는지 검증한다. |
| 5 · 낮음 | **파일마다 512 KiB 읽기 버퍼를 새로 할당한다.** 작은 파일이 많을수록 할당 횟수가 늘어난다. 앞서 별도 브랜치에서 21개 파일로 측정한 결과, 버퍼 재사용으로 21회가 1회가 됐고 전체 스냅샷 해시는 일치했다. | 기존 최적화 커밋 `8c6cee5`를 검토해 반영한다. 할당 감소는 측정됐으며 실제 실행 시간 개선 폭은 대표 프로젝트에서 별도 측정해야 한다. |

## 코드 근거

1. 제출 재시도는 `.hc/task.sh:57–71`, `.hc/task.ps1:49–64`에 있다. macOS 전송 전 화면 검사는 `.hc/task.sh:97`이다.
2. 전송 후 기록하는 순서는 `.hc/task.sh:120–128`, `.hc/task.ps1:161–170`에 있다. 재시도 시 기존 예약을 재사용하는 조건은 `.hc/scope.mjs:167–174`, wait의 기록 확인은 `.hc/task.sh:168–170`이다.
3. 공통 JSON 쓰기는 `.hc/scope.mjs:140`, 읽기 실패 처리는 135–139행, 전체 예약 열거는 159–165행이다.
4. 로그 선택은 `.hc/task.sh:143–150`, 구간 판정과 결과 출력은 151–161행이다.
5. 기준 브랜치의 버퍼 할당은 `.hc/scope.mjs:98`, 파일별 호출은 125행이다.

## 검증 결과와 범위

- 원본에서 `node --test .hc/scope.test.mjs`를 실행했다. 총 32건 중 31건 통과, 실패 0건, 건너뜀 1건이다. 테스트에는 파일시스템이 Unicode 정규화 별칭을 동일 파일로 취급할 때 건너뛰는 조건이 있다.
- `bash -n .hc/up.sh`와 `bash -n .hc/task.sh`는 각각 통과했다. 위 1–4번은 현재 코드의 호출 순서와 오류 경로에서 확인한 사항이다. 실제 권한 창에 키를 보내거나 실행 중인 작업을 강제 종료하는 시험은 수행하지 않았다.
- macOS·Windows 기동 스크립트 모두 현재는 권한 기록 읽기 실패를 처리한다. macOS agy 로그 탐색도 공백이 포함된 경로를 파일 단위로 처리한다. 이전 리뷰의 해당 문제들은 이번 수정 목록에서 제외했다.
- 두 지휘자가 동시에 같은 범위를 예약하는 경쟁은 기존 검증 문서에 기록돼 있다. 현재 지원하는 순차 예약을 유지하는 동안에는 별도 잠금 도입의 우선순위가 낮다. 운영 전제를 바꾸면 다시 검토해야 한다. 근거는 `docs/automation-validation.md:71`이다.
- 이번 검토는 작업 제출·대기, 범위 예약·검증 기록, 권한 감지와 로그 요약에 집중했다. Windows PowerShell 실행 환경과 실제 Herdr 종단 간 재시험은 이번 검증 범위에 포함되지 않았다.
