2026-11-21 기준. 공개 개발 중인 `herdr-agent-team`의 문서·기본 권한·Git 노출 방지를 점검했다. 안정화 또는 모든 환경의 호환성을 인증하는 문서가 아니다. 시작점은 `automation-improvements`의 `b531155`이며 이번 작업은 별도 `public-template-readiness` 브랜치에서 진행했다. `main` 병합·push·GitHub 설정 변경은 하지 않았다.

- README 영문·한글 상단에 **Work in Progress · 개발 진행 중**을 표시했다. 실제 OS 검증과 아직 구현/검증 중인 자동화를 구분하고 환경·버전 차이 및 실사용 전 권한/스크립트 확인을 안내한다.
- 기존 역할표·설치표·`.hc/` 구조·통신/보고 프로토콜을 유지했다. 첫 사용 순서는 프로그램 확인 → Herdr → 에이전트 설치/개인 로그인 → 프로젝트 설정 → 실행 → 통신/권한 → 작은 테스트 → 실제 개발이다.
- 프로젝트 설정은 `AGENTS.md` 5절을 사용한다. 깨끗한 checkout의 추적 파일만 복사하고 인증정보·작업 로그·브라우저 프로필·원래 저장소의 `.git`을 옮기지 않는다. 설치 상세 문서를 중복 생성하지 않고 기존 README 표와 지휘 절차를 연결했다.
- 문서 기반 Claude 지휘와 코드로 구현된 범위/재시도 검사를 구분했다. 완전 자율 스케줄러나 동시 지휘자 지원이 있다고 안내하지 않는다. 장기 방향은 선택적 위임·협업·피드백/재시도·통합 검증·안전한 소유 관리·이미지 병렬 흐름 개선이며 이번에 모두 새로 구현하지 않았다.

### `.gitignore` 보강

일반 `.env`와 변형, 인증 파일·개인 키, 에이전트 개인 설정/세션, 브라우저 인증 상태·HAR, 실행 로그와 개인 편집기 파일을 제외했다. `.env.example`·`.env.sample`·`.env.template`은 예시만 공유할 수 있도록 허용했다. `package.json` 같은 프로젝트 manifest나 공유 `.hc/` 스크립트·세션 정책 파일을 통째로 무시하지 않았다.

`git check-ignore --no-index`로 예시 경로를 검사했다. 파일이 이미 추적 중이면 ignore로 제거되지 않으므로 `git ls-files`, `git status`, staged diff도 함께 확인한다. 로그인 상태는 `.hc/qa/` 등 제외 경로에만 저장하고, 사용자 지정 파일명도 공개 전에 따로 점검한다.

## 기본 권한과 명시적 선택

- Codex 기동 코드는 변경하지 않았다. 기본은 `workspace-write`·`never`이며, `.hc/local.env`의 `CODEX_MODE=bypass`와 사용자 승인 기록이 있을 때만 기존 우회 모드를 선택한다. 네트워크와 보고용 소켓 접근이 허용되는 샌드박스이므로 완전 격리라고 안내하지 않는다.
- Antigravity 세션 설정의 기본 allow 목록은 macOS `command(hc send)`, Windows `command(regex:hc send .*)`만 남겼다. 기존 통신 문제를 해결한 Windows 보고 정규식은 유지했다. 기본 Node/브라우저 자동 실행과 특정 앱 설치 경로 읽기는 제거했다.
- 폭넓은 Node 실행·로그인된 실제 브라우저 접근은 스크립트/대상 URL을 확인한 뒤 사용자가 명시적으로 승인할 때만 프로젝트 세션 설정에 추가한다. 전역 설정을 넓히거나 `command(*)`를 넣지 않는다. 확장한 설정을 공개 템플릿의 기본값으로 커밋하지 않도록 diff를 확인한다.
- 허용 목록 밖 명령의 실제 동작은 도구의 자체 샌드박스/안전 판정에도 영향을 받는다. 승인 창이 항상 뜬다거나, 허용 목록이 모든 위험을 막는다고 보장하지 않는다. `hc send` 역시 로컬 다른 터미널에 메시지를 보낼 수 있어 지시된 수신자만 사용한다.
- 실행 중인 에이전트의 권한을 소급 변경하거나 터미널을 재시작하지 않았다. 다음 기동부터 축소된 기본 파일을 읽는다. 보고용 프로토콜과 task/up/scope 코드는 그대로다.

## 검증된 것과 아직 검증하지 않은 것

기존 검증 근거는 [자동화 검증 기록](automation-validation.md)과 [Windows 개발 기록](windows-setup-issues.md)에 남겼다. 당시 Windows 환경에서 코어 27개·백엔드 43개·브라우저 2개 뷰포트가 통과했고 이전 macOS 기동·통신·브라우저 검증 기록도 있다.

최신 task 자동화의 macOS 실제 실행, 이미지 생성과 개발의 병렬 시나리오, 다양한 버전/깨끗한 새 PC 설치는 아직 검증되지 않았다. 이번에 축소한 기본 allow 목록의 브라우저 무인 실행 역시 미검증이며 승인이 필요할 수 있다. 과거 확장 allow 목록의 E2E 통과를 현재 기본값의 결과로 바꾸어 표시하지 않는다.

이번 변경은 문서·ignore·세션 설정·LICENSE에 한정한다. README 내부 링크/두 언어 안내, JSON 구문/기본 allow 항목, ignore 허용·차단 경로, 파일/이력 재스캔, diff 공백 검사를 수행했다. 새로운 실제 에이전트 기동·E2E·macOS 검증을 수행한 것으로 세지 않는다.

## 라이선스와 외부 출처

기존 추적 파일·이력에는 LICENSE가 없었다. 사용자에게 MIT 도입을 제안하고 **명시적 승인을 받은 뒤** 저장소 소유자 `hwh950105`를 저작권자로 한 `LICENSE`를 추가했다. 내용은 [OSI MIT 원문](https://opensource.org/license/mit)을 기준으로 했다. 공개 상태만으로 코드의 재사용 라이선스가 정해지는 것은 아니라는 [GitHub 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)도 확인했다.

추적 파일은 자체 스크립트/테스트·설정·문서이며, 외부 라이브러리 소스·실행 파일·이미지·레이아웃 파일이 함께 배포되는 것은 발견하지 못했다. Node 코드의 import는 내장 모듈을 사용한다. 외부 도구 설치 링크와 API/명령 사용 안내는 해당 도구를 재라이선스하는 것이 아니다. 선택 레이아웃 bercail의 작성자 표기는 기존 README에 유지했고 레이아웃 자산은 포함하지 않았다. 이 파일 검토만으로 모든 코드의 창작 경위·권리 보유를 독립적으로 증명할 수는 없으므로, 외부 코드/에셋을 새로 가져올 때는 출처·원문 라이선스·고지 의무·호환성을 먼저 확인한다.
