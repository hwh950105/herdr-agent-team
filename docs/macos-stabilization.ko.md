# macOS 최종 최적화 보고서

## 1. 전체 상태

**PARTIAL.** Codex와 실제 Antigravity 터미널이 동시에 작업했다. Antigravity의 마지막 알림 전송은 실패했으며, 수정한 macOS `wait`가 보고 파일을 수신했다. 이번 작업은 Claude를 호출하지 않는 운영 조건을 적용했다.

## 2. 발견한 문제

- 기존 macOS 제출 확인은 작업 시작을 관측하지 못하면 자동으로 Enter를 전송했다. 이 사이에 터미널 입력 대상이 바뀔 수 있었다.
- 송신은 메시지를 보낸 뒤에만 작업 기록을 남겼다. 응답을 잃으면 같은 ID의 중복 송신 위험이 있었다.
- macOS `wait`가 보고 헤더의 ID를 검사하지 않았다. 로그 요약은 작업 헤더를 인용한 일반 출력이 들어 있는 최신 로그를 실제 작업 로그로 선택할 수 있었다.
- 현재 Antigravity의 개인 설정에는 `command(hc send)`가 있다. `hc read t5x --lines 180`으로 확인한 작업 화면에 따르면, 마지막 알림은 표준 샌드박스에서 셸이 `hc` 실행을 거부해 실패했다. 오류는 `zsh:1: operation not permitted: hc`, 종료 코드는 127이다.

## 3. 수정한 문제와 원인

- 전송 직전에 실제 터미널 주소와 실행 상태, 화면 조회 결과를 확인한다. 제출 확인은 상태·차례 검사만 수행한다.
- 전송 직전에 ID와 대상 주소, 이전 차례, 제출 확인 대기 상태를 기록한다. 제출을 확인한 경우에만 기록을 확정한다. 응답 손실 시 같은 ID의 전송 및 `nudge`가 멈추고 `wait`는 점검 필요 코드 4를 반환한다. `nudge`는 기존 차례 종료와 보고 누락을 확인한다.
- 보고 파일의 ID와 상태 형식을 검증한다. 로그 선택은 실제 사용자 입력 이벤트에서 해당 작업 헤더를 찾는다.

## 4. 수정 파일

- `.hc/task.sh` — macOS 송신·수신·로그 요약
- `.hc/task.test.mjs` — 모의 Herdr를 사용하는 macOS 회귀 테스트 7개
- `.hc/docs/lead.md` — macOS 점검 및 복구 절차

## 6. 미해결 문제

- Antigravity 알림의 직접 실패 원인은 셸 단계의 실행 거부로 확인했다. `hc` 실행을 거부한 구체적인 샌드박스 규칙과 도구 허용 목록의 런타임 매칭은 미확인이다.
- 수정된 macOS 송신 경로의 성공·실패는 모의 테스트로 검증했다. 실제 Antigravity 작업의 최초 송신은 코드 변경 전에 수행했다.
- 공유 범위 기록 JSON의 기록 중단 문제는 기존 감사 항목으로 남아 있다.

## 7. 권한 및 보안 위험

권한 설정, 계정, 인증정보를 변경하지 않았다. Codex의 실제 정책은 이 세션에 한해 확인했다. 기존 실행 스크립트의 화면 기반 감지는 오래돼 화면 밖으로 밀린 권한 변경 이력까지 확인할 수 없다. Antigravity의 과거 브라우저 검증 기록에는 샌드박스 밖 자동 심사 재시도가 있었고, 이번 읽기 전용 작업의 로그 추정치만으로 브라우저에서 같은 문제가 해결됐다고 판단할 수 없다.

## 8. 추가 권장 개선사항

보고 알림을 복구할 때는 Antigravity 샌드박스가 `hc` 바이너리 실행에 적용한 제한을 확인한다. macOS의 공유 상태 JSON을 원자적으로 저장하도록 보강한 뒤, 승인된 로컬 UI로 세 터미널 재사용부터 실패 후 수정과 통합까지 한 번에 재검증한다.

## 9. 실제 운영 가능 여부

**제한적으로 일상 개발에 사용 가능하다.** 순차 예약과 보고 파일 확인을 운영 기준으로 삼을 수 있다. 세 터미널의 무인 운영, 브라우저 권한 정책, 완전 자동 수정·통합까지 안정화됐다고 판정하려면 추가 실기기 검증이 필요하다.
