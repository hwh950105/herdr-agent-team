# 브라우저 검증 규칙 (Antigravity)

`브라우저: 필요`가 적힌 지시만 브라우저를 쓴다. 도구는 OS마다 다르다.

| | macOS | Windows |
|---|---|---|
| 도구 | ego lite (`ego-browser`) — 사용자가 로그인한 실제 브라우저 | Playwright — 로그인 정보가 없는 깨끗한 브라우저 |
| 시작 | `ego-browser skill` 출력을 `.hc/qa/<작업ID>/skill.txt`에 저장해 끝까지 읽고(`[ego-browser:skill] end of guide` 줄 확인) 그 사용법을 따른다 | 검증 스크립트를 `.hc/qa/<작업ID>/` 안에 만들어 **`node <스크립트> [인자...]` 단독 명령**으로 실행한다. 환경 변수 대입(`$env:X='...'; node ...`)이나 `;`·`&&` 결합은 허용 규칙에 맞지 않으므로 쓰지 않고, URL 같은 설정은 인자로 넘긴다(예: `node e2e/todo.e2e.mjs http://localhost:3456`). 스크립트도 증거로 남긴다 |
| 공간 | `taskSpace("<작업ID>")` 하나만 만들고 그 안에서만 작업한다. 사용자 탭(`openedBy: "unknown"`)은 건드리지 않는다. 끝나면 `task.finish({ keep: [] })`를 한 번 실행한다 | 스크립트가 띄운 브라우저는 스크립트 끝에서 `browser.close()`로 닫는다 |
| 중단·재개 | 로그인·2FA·CAPTCHA 등 사용자 조작이 필요하면 `finish()`하지 않고 `await task.handOff()`로 넘긴 뒤 `blocked`로 보고(공간 ID, 현재 URL, 필요한 조치). 나중에 지시문의 `이어받을 공간:`에 그 공간 ID가 오면 새 공간을 만들지 않고 그 공간에서 이어서 한다 | 로그인이 필요하면 지시문의 테스트 계정만 쓴다. 없으면 `blocked` |

권한:
- **승인 창:** `node`·`ego-browser` 실행은 승인 창이 뜰 수 있다. 키를 대신 누르지 말고 그 상태와 필요한 조치를 `blocked`로 보고한다.
- **샌드박스 밖 재실행:** agy 기본 Auto 모드에서는 샌드박스에서 막힌 명령(`ego-browser`·`hc send` 등)이 검토 에이전트 승인으로 샌드박스 밖에서 다시 실행될 수 있다. 그랬다면 보고의 검증 항목에 명령과 횟수를 적는다.
- **설정 불변:** 허용 목록(`.hc/agy-settings.*.json`, 사용자 설정 폴더의 파일)은 고치지 않는다. 반복 실행 권한은 사용자가 직접 추가한다(`.hc/docs/lead.md` 5절).

공통:
- **접속 범위:** `대상 URL:`에 적힌 출처와 경로 범위, 허용된 리다이렉트 출처 안에서만 이동한다. 벗어나면 더 조작하지 않고 `blocked`로 보고한다.
- **쓰기 금지:** 지시문에 테스트 계정·데이터와 허용 동작이 없으면 결제·삭제·글쓰기·설정 변경·메시지 전송은 하지 않는다. 쿠키·캐시·저장소 삭제, 브라우저 프로필 선택·가져오기도 하지 않는다.
- **증거:** 재현 절차, 기대 결과와 실제 결과, 스크린샷 경로(macOS는 `skill.txt`, Windows는 검증 스크립트도)를 보고한다. 모든 증거 파일은 `.hc/qa/<작업ID>/`에 **절대 경로**로 저장한다. 이 폴더는 `담당 파일:`에 없어도 쓸 수 있다.
- **시각 판단:** 스크린샷은 직접 열어 보고 판단한다. 자기가 구현한 화면을 검증할 때도 같은 기준을 적용한다. 문제를 찾으면 담당 범위 안이면 고친 뒤 다시 검증하고, 범위 밖이면 보고한다.
